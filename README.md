# Тестирование веб-приложения Buggy Cars Rating

![Manual QA](https://img.shields.io/badge/QA-manual%20testing-0f766e)
![Bugs found](https://img.shields.io/badge/defects%20found-13-b91c1c)

Учебный проект портфолио: ручное функциональное, негативное, UI/UX, accessibility и security-тестирование
публичного тренировочного сайта **Buggy Cars Rating** — приложения с намеренно заложенными дефектами.

> **Объект тестирования:** <https://buggy.justtestit.org>
> **Тип:** публичный QA-тренажёр (не production-система). Тестирование проводилось только в рамках
> разрешённого учебного сценария, без нагрузки, брутфорса и атак на инфраструктуру.

---

## Зачем этот репозиторий

Показать полный цикл работы тестировщика на реальном объекте:

1. **Планирование** — тест-план, границы и риски.
2. **Проектирование проверок** — чек-лист и 39 тест-кейсов.
3. **Выполнение** — ручные прогоны в браузере + инструментальные проверки (Lighthouse, DevTools, HTTP-заголовки).
4. **Документирование дефектов** — 13 баг-репортов с шагами, ожидаемым/фактическим результатом и скриншотами.
5. **Анализ** — сводка результатов, матрица трассируемости, выводы и рекомендации.

Всё подтверждено артефактами в каталоге [`evidence/`](evidence): скриншоты и отчёт Lighthouse.

## Что проверено и что работает

Негативные и позитивные проверки, которые **прошли** (важная часть отчёта — не только баги):

| Проверка | Результат |
|----------|-----------|
| Вход с неверным паролем | `Invalid username/password` — корректно |
| Несовпадение паролей при регистрации | Блокируется на клиенте: `Passwords do not match` |
| XSS через HTML в комментарии (`<b>…</b>`) | Экранируется, теги не исполняются |
| XSS через `<script>` | WAF отвечает 403, полезная нагрузка не проходит |
| Регистрация с валидными данными | Успешна, редирект на логин |
| Голосование за модель без входа | Недоступно, требуется авторизация |
| Сохранение валидного профиля (age 25) | Сохраняется и переживает перезагрузку |

## Как воспроизвести

1. Открыть <https://buggy.justtestit.org> в Chromium-based браузере.
2. Зарегистрировать тестового пользователя (логин и пароль — любые валидные; **не используйте реальные данные**).
3. Пройти по кейсам из [`docs/03-test-cases.md`](docs/03-test-cases.md); дефектные — по шагам из баг-репортов.
4. Для WEB-12: DevTools → Lighthouse → Analyze page load (Desktop) на `/overall`.
5. Для WEB-13: DevTools → Network → заголовки ответа главной страницы и запросов к API.

## Ограничения

- Объект — тренировочный сайт; часть дефектов заложена авторами намеренно.
- Тестирование однократное (один прогон), без регрессии после «исправлений» — чинить чужой сайт нельзя.
- Не проводилось: нагрузочное тестирование, тестирование мобильных приложений, пентест, проверка платёжных сценариев.
- Тестовые учётные данные в репозиторий не выкладываются.

---

## Чему научился

- Отделять «сайт сломан» от «сайт так задуман»: фиксировать ожидание и обосновывать его.
- Оформлять дефект так, чтобы разработчик воспроизвёл его с первого раза.
- Замечать не только функциональные баги, но и безопасность (сырые ошибки, CORS, отсутствие заголовков),
  доступность и SEO — то, что чаще всего пропускают на junior-позициях.
- Проверять негативные сценарии и убеждаться, что часть защиты работает (XSS-экранирование, WAF).
