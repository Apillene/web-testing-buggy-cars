# Тест-план — Buggy Cars Rating

| Поле | Значение |
|------|----------|
| Проект | Учебное тестирование веб-приложения Buggy Cars Rating |
| Объект | <https://buggy.justtestit.org> |
| Версия объекта | Публичная версия на дату прогона (2026-11-23) |
| Автор | Иван Войтков, intern QA |
| Тип тестирования | Ручное: функциональное, негативное, UI/UX, accessibility, security-smoke |
| Статус | Выполнено, отчёт закрыт |

## 1. Цель

Проверить ключевые пользовательские сценарии тренировочного сайта, найти и документировать дефекты,
оценить их влияние на пользователя и подготовить отчёт, пригодный для передачи разработке.

## 2. Что входит в объём

| Модуль | Проверяем |
|--------|-----------|
| Регистрация | Валидация полей, пароли, дубликаты, сообщения об ошибках |
| Авторизация | Вход/выход, неверные данные, доступ к защищённым страницам |
| Профиль | Просмотр и редактирование, валидация, сохранение, поведение после logout |
| Каталог (`/overall`) | Отображение моделей, сортировка, пагинация, данные |
| Карточка модели | Рейтинг, голосование, комментарии |
| Комментарии | Добавление, отображение, экранирование HTML |
| Общие элементы | Навигация, футер, тексты, консоль браузера |
| Нефункциональное | Accessibility, SEO, security-заголовки, CORS |

## 3. Что не входит

- Нагрузочное и стресс-тестирование.
- Пентест, сканирование уязвимостей, brute force.
- Мобильные приложения и нативные клиенты.
- Платёжные сценарии (их нет на объекте).
- Проверка бэкенда «изнутри» (нет доступа к коду и БД).

## 4. Стратегия

1. **Исследовательское тестирование** — пройти все страницы как пользователь, зафиксировать подозрительное.
2. **По чек-листу** — системно закрыть модули, чтобы не пропустить очевидное.
3. **По тест-кейсам** — воспроизводимые шаги для ключевых и негативных сценариев.
4. **Инструментальные проверки** — Lighthouse, DevTools (Network/Console/Application), анализ заголовков.
5. **Подтверждение дефекта** — минимум два независимых наблюдения (UI + сеть/повторный прогон), скриншот.

Подробнее: [`06-environment.md`](06-environment.md).

## 6. Тестовые данные

- Отдельная обезличенная тестовая учётная запись `ivanov.ivan.qa` (имя **Ivan**, фамилия **Ivanov**),
  пароль не публикуется. Для негативных проверок используются логины вида `ivanov.ivan.*`.
- Для негативных проверок: пароли `123`, `abc`, возраст `0`, `abc`, `-1`, gender `Banana`, e-mail без TLD.
- Реальные персональные данные не использовались.

## 7. Критерии входа

- Сайт доступен, регистрация и вход работают.
- Известны основные маршруты: `/`, `/overall`, `/profile`, `/comments`, `/register`, `/login`.

## 8. Критерии выхода

- Пройдены все пункты чек-листа и все тест-кейсы (Pass/Fail).
- Каждый Fail подтверждён и оформлен баг-репортом либо признан «так задумано».
- Собраны скриншоты/отчёты для каждого дефекта.
- Заполнена сводка и матрица трассируемости.

## 9. Риски и допущения

| Риск | Влияние | Как снижали |
|------|---------|-------------|
| Сайт меняется без предупреждения | Шаги перестанут воспроизводиться | Фиксировали дату прогона и скриншоты |
| Часть «багов» — задумка авторов | Ложные дефекты | Проверяли ожидание по здравому смыслу и стандартам (WCAG, HTTP) |
| Ограничение доступа к API | Не всё видно в UI | Смотрели Network и ответы API |
| WAF блокирует полезные нагрузки | Ложное «всё безопасно» | Отмечали, что блокировка — защита, а не доказательство отсутствия XSS |
| Аккаунт может быть удалён модератором | Потеря тестовых данных | Один прогон, данные не переиспользовались |
