# Баг-репорты — Buggy Cars Rating

Шкала severity:

| Уровень | Значение |
|---------|----------|
| Critical | Потеря данных, обход авторизации, утечка чужих данных |
| Major | Ключевой сценарий не работает или вводит пользователя в заблуждение |
| Minor | Работает, но с заметным дефектом/неудобством |
| Trivial | Косметика, опечатки |

Окружение для всех отчётов: Windows 11, Chromium-based браузер (актуальная версия), <https://buggy.justtestit.org>,
прогон 2026-11-23. Скриншоты — в [`../evidence/`](../evidence).

## WEB-01

**Пароль короче 6 символов: пользователю показывается сырая ошибка бэкенда**

| Поле | Значение |
|------|----------|
| Severity | Major |
| Priority | High |
| Компонент | Регистрация |
| Воспроизводимость | 100 % (3/3) |
| Evidence | [`01-register-weak-password-error.jpg`](../evidence/01-register-weak-password-error.jpg) |

**Шаги**

1. Открыть `/register`.
2. Заполнить Login, First Name, Last Name.
3. В Password и Confirm Password ввести `123`.
4. Нажать Register.

**Ожидаемый результат:** понятное сообщение валидации на уровне формы, например «Пароль должен содержать
не менее 6 символов»; запрос на сервер не отправляется.

**Фактический результат:** форма отправляется, пользователю показывается техническая ошибка бэкенда:
`InvalidParameter: 1 validation error(s) found. - minimum field size of 6, SignUpInput.Password.`

**Влияние:** пользователь не понимает, что исправить; раскрываются детали внутреннего API и имена полей.

**Рекомендация:** клиентская валидация длины + серверное сообщение, маппинг ошибок API в человекочитаемые тексты.

## WEB-03

**Профиль принимает недопустимые значения и теряет данные**

| Поле | Значение |
|------|----------|
| Severity | Critical |
| Priority | High |
| Компонент | Профиль |
| Воспроизводимость | 100 % (3/3) |
| Evidence | [`02-profile-invalid-data-saved.png`](../evidence/02-profile-invalid-data-saved.png) |

**Шаги**

1. Войти в аккаунт, открыть Profile.
2. В поле Gender ввести `Banana`, в Age — `0`.
3. Нажать Save.
4. Перезагрузить страницу профиля.

**Ожидаемый результат:** Gender — только значение из списка, Age — целое в разумном диапазоне (например, 1–149);
некорректные данные отклоняются с сообщением об ошибке.

**Фактический результат:** профиль сохраняется, показывается `The profile has been saved successful`.
После перезагрузки Age = 0 отсутствует (поле пустое) — данные молча потеряны; Gender `Banana` сохраняется.

**Влияние:** в систему попадают невалидные данные; пользователь получает ложное подтверждение успеха
и теряет введённое значение. Потенциально ломает отчёты и выборки по полу/возрасту.

**Рекомендация:** серверная валидация enum для Gender и диапазона для Age; не сообщать об успехе при
частичном сохранении; вернуть ошибку с указанием поля.

| Evidence | наблюдение в браузере, скриншот не требуется |

2. Открыть Profile через меню — страница работает.

## WEB-13

**Отсутствуют security-заголовки; небезопасная CORS-политика**

| Поле | Значение |
|------|----------|
| Severity | Major |
| Priority | High |
| Компонент | Инфраструктура / API |
| Воспроизводимость | 100 % |
| Evidence | DevTools → Network → Response Headers |

**Шаги**

1. Открыть главную страницу.
2. DevTools → Network → выбрать документ → Response Headers.
3. Повторить для запросов к API.

**Ожидаемый результат:** присутствуют `Content-Security-Policy`, `Strict-Transport-Security`,
`X-Frame-Options` (или `frame-ancestors`), `Referrer-Policy`, `X-Content-Type-Options: nosniff`.
CORS не разрешает одновременно `*` и credentials.

**Фактический результат:** перечисленных заголовков нет. API отдаёт
`Access-Control-Allow-Origin: *` вместе с `Access-Control-Allow-Credentials: true`.

**Влияние:** повышенный риск кликджекинга, XSS-последствий, утечки referrer; небезопасная CORS-конфигурация
может позволить чтение ответов с чужих origin при наличии cookies.

**Рекомендация:** добавить заголовки на уровне reverse proxy; для CORS использовать явный allowlist origin
и не сочетать `*` с credentials.
