## Ключевые выводы

1. **Самое опасное — WEB-05**: после выхода профиль показывает данные предыдущего пользователя.
   Это утечка персональных данных, а не косметика.
2. **WEB-03** сочетает отсутствие валидации и ложное сообщение об успехе с молчаливой потерей возраста —
   классический пример «зелёного» UI при битом бэкенде.
3. **WEB-01/02/04** показывают отсутствие слоя обработки ошибок: пользователь видит исключения и «Unknown error».
4. **WEB-07** — ошибка граничных условий пагинации; лечится проверкой диапазона на сервере.
5. **WEB-12/13** — системные пробелы шаблона: доступность, SEO и security-заголовки не настроены вовсе.

## Что работает хорошо

- Базовая аутентификация: неверные данные дают одинаковый нейтральный ответ.
- Пароли не совпадают — блокируется на клиенте.
- HTML в комментариях экранируется, `<script>`-нагрузка режется WAF.
- Валидные данные профиля сохраняются и переживают перезагрузку.
- HTTPS и сертификат в порядке, смешанного контента нет.
